# 产品逻辑规范：第三方网站退出登录对下载任务的影响

**版本:** v1.0
**日期:** 2026-01-20
**场景:** 用户在 StreamFab 内置浏览器中退出了流媒体网站（如 Netflix）的账号。

---

## 1. 核心逻辑总表

| 任务状态 (Task State) | 是否允许继续 (Action) | 核心原因 (Technical Rationale) | 用户界面表现 (UI Behavior) |
| :--- | :--- | :--- | :--- |
| **Detected / Queueing**<br>(已识别 / 待下载) | **🔴 禁止 (Blocked)** | **无法获取解密密钥 (License)。**<br>此时尚未发起 License Request。启动任务需要有效的 Cookie/Session，退出登录导致鉴权凭证失效，请求会被服务端拒绝 (403 Forbidden)。 | **清空列表 + 强引导：**<br>隐藏待下载任务列表，显示全屏“请登录”占位图 (Empty State)，防止用户误操作。 |
| **Downloading**<br>(下载中) | **🟢 允许 (Allowed)** | **密钥已缓存 (Key Cached)。**<br>下载启动瞬间已成功获取密钥并保存在内存中。后续的分片下载 (Segment Downloading) 仅与 CDN 交互，通常不校验登录态。 | **保持现状：**<br>任务继续运行。建议增加“⚠️”黄灯提示，告知用户当前处于离线/风险状态。 |
| **Failed**<br>(下载失败) | **🔴 禁止重试 (Blocked)** | **需重新建立会话。**<br>“重试”本质上是一个全新的下载请求，需要重新走一遍 License 申请流程，无登录态必挂。 | **弹窗提示：**<br>点击重试时，弹出“账号已退出，请重新登录”对话框。 |
| **Paused**<br>(已暂停) | **🔴 禁止恢复 (Blocked)** | **会话过期 (Session Expired)。**<br>暂停期间 Session 可能已过期或被销毁，恢复任务时通常需要重新验证权限。 | **状态置灰 / 提示登录：**<br>点击恢复时提示需重新登录。 |
| **Completed**<br>(下载完成) | **⚪ 无影响 (No Impact)** | **本地资产。**<br>文件已解密并封装为本地 MP4，与在线账号状态彻底解耦。 | **正常显示：**<br>保留在“已完成”列表中。 |

---

## 2. 关键设计决策 (Design Decisions)

### 🛡️ 待下载区的“防呆设计” (Poka-Yoke)
为了避免用户在退出登录后点击“开始全部”导致批量报错，我们采取**物理屏蔽**策略：
*   **策略:** 当检测到 Logout 事件时，**强制隐藏**所有 Queueing 状态的任务。
*   **目的:** 让错误根本无法发生 (Make error impossible)，而不是等报错了再解释。

### ⚠️ 下载中的“尽力而为” (Best Effort)
虽然允许下载中任务继续，但需明确这是一个**非承诺服务**：
*   **风险:** 极少数情况下（如 Key Rotation 机制），服务端可能中途要求换密钥。此时因无登录态，任务会失败。
*   **处理:** 若发生此类失败，错误码应映射为 `AUTH_EXPIRED`，明确告知用户是账号原因。
