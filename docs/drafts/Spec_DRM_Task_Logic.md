# 最终决策：用户中途退出对下载任务的影响 (Impact Analysis)

基于我们对 DRM License 机制的深入剖析，以下是**符合技术事实**的产品逻辑修正案。

## 1. 核心结论
**“中途退出” = “销毁钥匙凭证”。**
这就好比你在银行排队办业务，轮到你签字（Request License）时，你把身份证扔了。

*   **待下载 (Scheduled/Queueing):** **必死。** 还没轮到它拿钥匙，身份证就没了。
*   **下载中 (Downloading):** **大概率存活。** 钥匙已经揣兜里了。
*   **下载失败 (Failed):** **必死。** 重试等于重新排队，需要再次出示身份证。

---

## 2. 修正后的逻辑状态表 (Revised Logic Table)

| 任务状态 | 场景描述 | 你的旧逻辑 | ✅ 修正后的逻辑 | 核心理由 (Technical Root Cause) |
| :--- | :--- | :--- | :--- | :--- |
| **Detected / Queueing**<br>(已识别/待下载) | 用户在任务**开始前**退出了 Netflix 账号 | **允许继续** ❌ | **🚫 自动暂停 / 报错** | **No License:** 此时还没拿钥匙。一旦启动，License Request 会因无 Cookie 直接返回 `403 Forbidden`。 |
| **Downloading**<br>(下载中) | 任务**进行中**，用户在浏览器退出了账号 | **允许继续** ✅ | **⚠️ 允许继续**<br>(但在 UI 上给个黄灯警告) | **Key Cached:** 钥匙通常在下载启动瞬间已获取并缓存在内存中。后续下载分片只走 CDN，不验证 Cookie。 |
| **Failed**<br>(下载失败) | 任务失败，用户点击**重试**时已退出账号 | **禁止重试** ✅ | **🚫 禁止重试**<br>(提示需重新登录) | **New Session:** 重试本质上是一次全新的会话，必须重新申请 License。 |
| **Paused**<br>(已暂停) | 用户暂停任务 -> 退出账号 -> 点击**恢复** | *(未定义)* | **🚫 禁止恢复** | **Session Expired:** 暂停太久会导致 Session 过期，恢复时通常需要重新鉴权。 |

---

## 3. 给开发/测试的验收标准 (AC)

### AC1: 待下载拦截 (The Gatekeeper)
*   **Given:** 用户添加了任务 A 到队列，状态为 `Waiting`。
*   **When:** 用户在内置浏览器点击 Logout。
*   **Then:** 任务 A 状态应立即变更为 `Suspended (需登录)`，或在尝试启动时弹出“请登录”对话框。

### AC2: 下载中容错 (The Survivor)
*   **Given:** 任务 B 正在下载 (进度 50%)。
*   **When:** 用户 Logout。
*   **Then:** 任务 B 继续下载直到完成。
*   **Exception:** 如果 Netflix 服务端执行了**强制 Key Rotation** (极少见) 导致下载报错，错误文案应显示：“会话失效，请重新登录”。

### AC3: 批量操作保护
*   **Given:** 队列里有 10 个任务。
*   **When:** 第 1 个下载时用户 Logout。
*   **Then:** 第 1 个任务可能成功，但第 2-10 个任务**必须全部自动暂停**，不能连续报错刷屏。
