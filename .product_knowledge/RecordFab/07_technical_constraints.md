# 07 技术约束（Technical Constraints）

## 系统要求（已确认）
- 当前支持平台：仅 Windows
- 操作系统：Windows 11 / 10 / 8.1 / 8 / 7（32/64 bit）
- CPU：Intel i3 或以上
- 内存：4GB RAM 或以上
- 磁盘：40GB 可用空间或以上
- 网络：需要持续联网
- 授权：使用时必须联网验证

## 已确认的能力约束
1. 输出规格约束
- 当前公开为 720p / 1080p。
- 输出格式当前公开为 MP4。

2. 站点能力约束
- 虽然支持大量流媒体站点，但高速录制并非全站点都可用。
- 具体表现为：部分站点只能以 1x 录制。

3. 运行时约束
- 录制过程中，RecordFab 内的其他操作会被限制，以保证更平滑的录制。
- 这意味着交互设计不能假设用户能在同一会话里自由切换大量其他功能。

4. 当前公开可配置项约束
- FAQ 当前明确支持的自定义项只有：
  - 输出分辨率
  - 录制速度

5. 当前版本能力边界
- 输出格式：MP4 和 MKV 均支持。
- 不支持并发录制（每次只能录制一个任务）。
- 不支持计划/定时录制（已有用户反馈，列入需求池，尚未上线）。
- 最小化到后台时录制可继续进行。
- 部分站点仅支持 1x 录制速度，产品不做提示，静默按 1x 执行。

6. 设置项边界
- 除录制核心参数外，还存在通用设置项，例如输出目录。
- 这类设置项应与录制核心参数分层表达，避免混在录制确认弹窗里。

7. 内部资料中的技术补充
- 底层曾提到“录制模式”和 “Re-encoding 模式”组合。
- 当前可作为已知背景知识，但不要在没有研发确认的情况下直接转写为对外功能承诺。

## 输出目录
- 默认目录：`%AppData%\DVDFab\RecordFab\`
- 用户可在设置中修改。

## 对设计和 PRD 的约束要求
1. 任何新功能都不能突破当前公开的系统要求口径。
2. 任何“后台运行”“定时录制”“云端同步”等提案都应先过技术可行性确认。
3. 对站点差异必须允许按站点降级，而不是统一承诺。
