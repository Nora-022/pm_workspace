## T-01 “无视频 / 无法进入分析”终态缺失

**现象**：  
页面不存在可分析视频，或当前线索不足以进入完整分析时，前端可能仍停留在“分析中”。

**当前链路表现**：

- 插件先上报 `url_change` 和 `response_data`
- CoApp 会先判断 URL 是否值得继续分析
- 但当前接口文档没有明确给出“无视频”“无足够线索”“无法进入分析”的稳定终态消息
- 如果没有返回 `analyze_result failed` 或空结果，前端只能继续维持 `analyze_status`

**影响**：

- 用户会误以为系统仍在分析
- 页面没有视频时，界面无法自然回落到“未检测到”或失败提示
- 产品侧无法稳定区分：
  - 没有视频
  - 线索不足
  - 分析失败
  - 仍在分析

**建议**：

- 在接口层补一个明确终态，用于表示：
  - 无可分析视频
  - 当前页面不满足进入分析条件
  - 分析过程失败
- 前端再基于该终态结束“分析中”并回到空状态或失败提示

## T-02 URL 判断规则未在接口文档中公开

**现象**：  
接口文档能确认 CoApp 会在 URL 变化后先做支持性判断，但没有公开 URL 匹配算法和页面类型判定规则。

**当前已知**：

- 插件通过 `url_change` 发送 URL
- CoApp 会先判断该 URL 是否支持
- URL 不支持时，不继续分析

**未知点**：

- 是否只按 host 判断
- 是否按 path / query / route 细分页面类型
- 是否不同插件维护不同 URL 规则集

**影响**：

- 产品难以准确设计“什么时候应该进入检测中”
- 研发外部协作时，容易把“URL 支持”和“已检测到视频”混为一谈

**建议**：

- 补一份 URL 支持性判断说明
- 至少区分：
  - 支持站点但非视频页
  - 候选视频页
  - 已进入分析页

## T-03 分析阶段的阻断策略较重

**现象**：  
接口文档中要求分析过程中弹出提示，阻止用户操作网页。

**影响**：

- 当前交互是强阻断式分析，不是后台静默分析
- 该策略如果持续时间过长，会显著影响用户浏览体验

**建议**：

- 后续需要结合实际插件产品策略确认：
  - 是否所有插件都必须强阻断
  - 哪些插件或页面可以降级为轻提示

## T-04 插件与 CoApp 的职责边界容易被误解

**现象**：  
容易把当前架构误解为：

- 插件负责检测视频
- CoApp 负责分析视频

**更准确的事实**：

- 插件负责线索采集
- CoApp 负责判断是否进入分析、执行分析并返回结果

**影响**：

- 若产品设计按“插件先独立检测成功/失败”去建模，容易和当前接口状态机不一致

**建议**：

- 后续在需求、设计和接口说明里统一使用：
  - `插件采集线索`
  - `CoApp 判断并分析`
  - `系统需要有明确终态`
