# 05 设计原则与规范（Design Principles）

## 设计原则（3-5 条）
1. 框架稳定，模式复用
2. 意图优先，异步校验
3. 状态完整，反馈就地
4. 上下文严格绑定

## 每条原则的对 / 错示例

### 原则：框架稳定，模式复用
- 对：Popup 与 Sidebar 复用同一套 `Detected / Downloads` 主结构，用户切换展示方式后仍能快速定位功能。
- 错：Popup 和 Sidebar 拆成两套不同信息架构，导致用户切换后需要重新学习。

### 原则：意图优先，异步校验
- 对：用户点击下载后立即创建任务并跳转 `Downloads`；环境问题在任务卡片中异步反馈。
- 错：点击下载后先做技术环境阻断校验，任务未创建，要求用户重复操作。

### 原则：状态完整，反馈就地
- 对：检测中、空状态、未登录、未安装 CoApp、CoApp 更新、失败重试等状态都有明确界面承接，且优先在当前模块内反馈。
- 错：不同异常都复用同一种笼统提示，或把所有问题都放到全局弹窗里处理。

### 原则：上下文严格绑定
- 对：`Detected` 列表与当前页面 URL 生命周期绑定；页面刷新或跳转后立即清空并重新检测。
- 错：页面切换后保留上一页面检测结果，导致用户处理“幽灵”任务。

## 插件级规范
- `Detected` 与 `Downloads` 是该插件的一级骨架，应长期保持稳定。
- 下载前设置、Playlist 选择、任务队列、状态页都属于同一套工具型框架中的子层级。
- 插件级文档只记录该插件自己的结构和交互约束。
- 通用视觉规范统一引用 `_common/references/visual_guidelines.md`，不在本文件重复展开。
- 通用交互结构与页面职责统一引用 `_common/references/ux_patterns.md`，不在本文件重复展开。
- 通用页面骨架与结构尺寸参考统一引用 `_common/references/layout_specs.md`，不在本文件重复展开。

## 组件使用约束
- Tab：
  - 一级结构固定为 `Detected` 与 `Downloads`。
  - 二者是该插件的核心框架，不应轻易改名或替换。
- 弹窗：
  - 用于下载前设置、Playlist 批量选择或商业级阻断。
  - 技术异常优先卡片内反馈。
- 列表 / 卡片：
  - `Detected` 使用视频结果卡片。
  - `Downloads` 使用任务卡片。
  - 状态与操作同位展示，支持快速 `Retry / Cancel / Open Folder`。
