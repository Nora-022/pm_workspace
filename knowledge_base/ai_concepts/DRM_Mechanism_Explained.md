# 为什么下载流媒体视频必须请求 DRM License？

## 1. 核心比喻：保险箱与钥匙
想象你在网上买了一本电子书（Netflix 视频）。
*   **加密视频文件 (Encrypted Content):** 商家发给你的是一个**上了锁的保险箱**。任何人都可以下载这个保险箱（甚至可以复制给别人），但没有钥匙打不开，里面是一堆乱码。
*   **DRM License (许可证):** 这就是**钥匙**。
*   **播放/下载器:** 就是**开锁匠**。

## 2. 下载流程拆解 (The Workflow)
当你点击“下载”时，后台其实发生了两件独立的事情：

1.  **下载保险箱 (Download Content):**
    *   下载视频数据流（.mp4 / .m4s）。这些数据是经过 AES-128 等算法**加密**的。
    *   *注意：这一步通常只需要 CDN 的访问权限，有时候甚至不需要强登录态。*

2.  **获取钥匙 (Acquire License) —— 关键步骤！**
    *   你的下载器发现视频是加密的，就会向 Netflix 的 **License Server (KMS)** 发起请求：“我是用户 A，我有这个视频的播放权吗？请给我解密钥匙。”
    *   **鉴权 (Authentication):** License Server 会立刻检查你的 **Session Cookie / Token**。
        *   ✅ **登录且有会员：** 发放 License（钥匙）。
        *   ❌ **未登录/已退出：** 拒绝请求（403 Forbidden）。

## 3. 为什么要分开做？(Why Separate?)
*   **安全性:** 钥匙（License）通常有有效期（比如 48 小时）。即使你把视频文件（保险箱）拷走了，过期后没有新钥匙也看不了。
*   **效率:** 视频文件很大（几 GB），适合放在 CDN 随便下；钥匙很小（几 KB），适合由核心服务器严加看管。

## 4. 回到你的场景
为什么 **Detected (已识别)** 状态下，用户退出后不能下载？

*   **Detected** 阶段，你只是看到了“保险箱”在哪里（拿到了 URL）。
*   当你点击 **Download** 时，下载器试图去申请“钥匙”。
*   此时用户已 Logout -> **无法出示身份证（Cookie 失效）** -> **拿不到钥匙**。
*   **结果：** 就算你能把 2GB 的加密视频下下来，因为没有 License，它也是一堆废数据，根本播放不了。

**结论：**
流媒体下载不仅仅是“文件传输”，它本质上是一次**“资产授权”**过程。没有登录态，就无法完成授权。
