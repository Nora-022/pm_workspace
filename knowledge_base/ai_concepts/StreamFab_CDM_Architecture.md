# StreamFab 技术揭秘：CEF 浏览器与内置 CDM 的关系

## 1. 核心误区澄清
**用户疑问：** "StreamFab 内置了一个 CEF 浏览器，是指用这个浏览器自带的 CDM 吗？"

**答案：** **不是。** (或者说，不完全是)。

*   **CEF 自带的 CDM** 是“官方良民”。它是一个黑盒子，只能用来**播放**。它接收加密流，输出画面，**严禁**输出密钥或解密后的文件。
*   **StreamFab 使用的 CDM** 是“魔改卧底”。它通常是一套独立编译的解密库（来源于泄露的 Android L3 或 Chrome CDM 代码），它的唯一目的就是**骗取并导出密钥**。

## 2. 架构拆解：双核协作模式

可以将 StreamFab 的工作原理看作是**“前台业务员”**与**“后台大盗”**的配合。

### 角色 A：前台业务员 —— CEF 浏览器 (The Browser Wrapper)
*   **身份：** 一个标准的 Chromium 浏览器壳。
*   **任务：**
    *   **模拟正常用户：** 让用户登录 Netflix/Amazon，处理验证码，通过网站的安全检查。
    *   **诱骗数据：** 访问视频播放页，触发网站下发 **MPD/M3U8 (元数据)** 和 **PSSH (加密头信息)**。
    *   **维持会话：** 保持 Cookie 鲜活。
*   **局限性：** 如果你只用 CEF，你只能在线看，没法存。因为它的 CDM 也是受保护的，无法导出数据。

### 角色 B：后台大盗 —— 内置魔改 CDM (The Decryption Core)
*   **身份：** 编译在 StreamFab 主程序里的一个 DLL/SO 模块。通常基于**泄露的 Widevine L3 CDM 源码**。
*   **任务：**
    *   **冒名顶替：** 拿到 CEF 抓到的 PSSH 和 Cookie 后，**自己构造**一个 License Request。
    *   **伪造设备：** 它会对 Netflix 服务器说：“嘿，我是一台 Google Pixel 手机（其实是 StreamFab），这是我的设备证书。”
    *   **劫持密钥：** 服务器验证通过后，发回 License（包含密钥）。普通的 CDM 会把密钥藏在受保护内存里，但这个“魔改 CDM”会直接把密钥**吐出来**（Dump）。
    *   **离线解密：** 拿着密钥，把下载下来的加密 .mp4 文件解密成无 DRM 的文件。

## 4. 深度释疑：为什么必须“伪装成手机”？
**用户核心疑问：** "我之前的理解是 StreamFab 复制一份 CEF 的请求去拿密钥，这个理解错了吗？为什么要伪装成手机？"

### 4.1. 你的理解“对了一半”，但关键的一半错了
你之前的理解是：
> CEF 发请求 -> StreamFab 复制这个请求 -> 发送 -> 拿到密钥

**错在哪里？**
*   **公钥/私钥匹配问题：**
    *   DRM 请求里包含了一个核心信息：**“我是谁” (Device Certificate)**。
    *   如果你原封不动地复制 CEF 的请求，你告诉服务器的是：“我是 CEF”。
    *   服务器会用 **CEF 的公钥** 加密返回的 License。
    *   **结果：** 这个 License 只有 **CEF 肚子里的那个正版 CDM** 能解开。StreamFab 截获了这个 License 也没用，因为它没有 CEF 的私钥（那是 Google 严防死守的机密）。

**正确的流程是：**
> CEF 拿到 PSSH (锁的型号) -> StreamFab **换用自己的身份证 (Android CDM)** 重新构造请求 -> 发送 -> 拿到**为我加密**的密钥 -> 成功解开

### 4.2. 为什么要伪装成手机 (Android)？
既然要用自己的身份证，为什么偏偏选“手机”的身份证？

1.  **软柿子好捏 (Security Level L3):**
    *   **PC 浏览器 (Chrome VMP):** 防护极其严密，代码高度混淆，很难提取出私钥。
    *   **Android (Widevine L3):** 历史上，很多低端安卓机或旧版安卓系统的 Widevine L3 实现是**纯软件**的，且防护较弱。黑客更容易从这些旧设备里提取出有效的 **Device ID 和 Private Key**。

2.  **通用性强:**
    *   只要搞到一套 Android L3 的密钥，几乎可以通吃所有支持安卓播放的流媒体网站。

3.  **代价：画质限制 (The Trade-off)**
    *   因为 L3 安全级别低，Netflix 等厂商通常**只给 L3 设备发 720p 或 1080p 的视频**，绝不发 4K。
    *   这就是为什么大多数下载器（包括 StreamFab）很难下载真正的 4K HDR 内容，通常最高止步于 1080p。如果能下 4K，通常意味着他们搞到了更高级别（L1）的泄露密钥（非常稀有且昂贵）。

## 5. 总结3. 完整“偷天换日”流程

1.  **嗅探 (Sniffing):**
    *   用户在 **CEF** 里打开视频。
    *   StreamFab **网络拦截模块** 抓包，拿到 `MPD URL` (视频地址) 和 `Auth Cookie` (身份证)。

2.  **构造 (Forging):**
    *   StreamFab 不使用 CEF 去请求 License（因为 CEF 拿到了也不给它）。
    *   StreamFab 启动内部的 **魔改 CDM**，使用刚才抓到的 Cookie，向 License Server 发起**全新的请求**。

3.  **欺骗 (Spoofing):**
    *   License Server 看到合法的 Cookie 和合法的（虽然是模拟的）设备证书，发放 License。

4.  **解密 (Decrypting):**
    *   魔改 CDM 收到 License，提取出 `AES-128 Key`。
    *   StreamFab 下载加密视频分片，用 Key 逐个解密，合并成 MP4。

## 5. 总结
StreamFab 里的 **CEF** 只是一个**“诱饵”**和**“环境模拟器”**。
真正干活（解密）的是它背后集成的那个**“破解版 CDM 模块”**。

这就是为什么：
*   哪怕 CEF 升级了，只要破解版 CDM 的证书没被封，下载依然有效。
*   反之，如果 Google 封禁了那批泄露的 L3 CDM 证书，StreamFab 就算能播放（CEF 正常），也无法下载（破解模块失效），此时就会出现“Analyzing...”无限失败。
