# DRM 攻防全景：常用加密策略与破解方案 (Encryption Strategies vs. Decryption Tactics)

为了让你对整个流媒体下载技术有更宏观的认识，我们将市面上常见的视频保护技术分为四个等级。StreamFab 这类软件的核心能力，就是针对不同等级采用不同的“撬锁”策略。

---

## 🟢 Level 1: 防君子不防小人 (HLS/AES-128 Clear Key)

这是最基础的保护，常见于小型网站或不重要的内容。

*   **🛡️ 加密策略 (Defense):**
    *   视频切片 (.ts) 被 AES-128 加密。
    *   **弱点：** 解密密钥 (Key) 的获取地址 (URI) 通常直接明文写在 m3u8 文件里。虽然 Key 文件本身可能需要 Cookie 才能访问，但一旦拿到 Key，解密过程是公开透明的，不需要复杂的 DRM 模块。
*   **⚔️ 破解/下载方案 (Tactics):**
    *   **直接嗅探 (Sniffing):** 浏览器抓包 m3u8，提取 Key URI。
    *   **下载解密:** 只要有访问 Key 的权限（Cookie），FFmpeg 或任何普通下载器都能直接下载并解密。
    *   **难度:** ⭐ (极低)

## 🟡 Level 2: 软件级 DRM (Widevine L3) —— StreamFab 的主战场

这是目前最主流的保护方式，覆盖了 90% 的 1080p 流媒体内容 (Netflix, Amazon, Disney+ 的 Web 端)。

*   **🛡️ 加密策略 (Defense):**
    *   **核心机制：** 视频内容加密，密钥分发由 Google Widevine CDM 控制。
    *   **安全等级 (L3):** 允许在**普通 CPU/内存**环境中进行解密。
    *   **弱点：** 因为解密逻辑跑在通用的安卓系统或浏览器软件层，黑客容易从内存或被 Root 的旧设备中提取出**私钥 (Private Key)**。
*   **⚔️ 破解/下载方案 (Tactics):**
    *   **伪装欺骗 (Spoofing):** 也就是我们之前讨论的“伪装成旧款安卓手机”。
    *   **密钥导出 (Key Dumping):** 利用泄露的 L3 CDM 模块，在申请 License 时将 Content Key 导出。
    *   **画质限制:** 厂商知道 L3 不安全，所以通常**只给发 1080p 或 720p** 的视频源。
    *   **难度:** ⭐⭐⭐ (中等，依赖泄露的 CDM)

---

## 🔴 Level 3: 硬件级 DRM (Widevine L1 / PlayReady SL3000)

这是 4K/HDR 内容的“铜墙铁壁”。

*   **🛡️ 加密策略 (Defense):**
    *   **核心机制：** **TEE (Trusted Execution Environment)**。
    *   **安全等级 (L1):** 视频解密过程必须在 CPU 的**独立安全区域 (Secure World)** 进行，解密后的画面直接送往显卡/屏幕。内存里永远不会出现明文视频数据，操作系统也无法读取 TEE 内部的密钥。
    *   **强硬手段:** 如果设备不支持 L1 (比如普通 PC 浏览器)，服务器直接拒绝下发 4K 视频流。
*   **⚔️ 破解/下载方案 (Tactics):**
    *   **方案 A - 降级攻击 (Downgrade):** 放弃 4K，伪装成 L3 设备去下 1080p (这是 StreamFab 的常规做法)。
    *   **方案 B - 漏洞利用 (Exploit):** 极少数黑客挖掘到了特定硬件芯片 (如某些电视盒子) 的 TEE 漏洞，能导出 L1 密钥。这种 CDM 极其稀有，且一旦公开会被 Google 秒封。
    *   **方案 C - 录屏 (Screen Recording):** 既然解密不了，就用采集卡录制显卡输出的画面。这是最笨但最通用的办法 (StreamFab 的所谓“高帧率录制模式”就是这个)。
    *   **难度:** ⭐⭐⭐⭐⭐ (极高)

## 4. 深度释疑：什么是“L1 流”和“L3 流”？
**用户核心疑问：** "流还分 L1、L2、L3 吗？这是什么意思？"

**答案：** 准确地说，**流 (Stream) 本身不分等级，但“许可证 (License)”分等级。** 而服务器会根据你能申请到的许可证等级，决定给你发哪种画质的流。

### 4.1. 潜规则：等级森严的“发片策略”
Netflix 等厂商为了保护高价值内容，制定了一套严格的**“看人下菜碟”**策略：

| 你的设备安全等级 | 你能拿到的 License | 服务器愿意给你的流 (Stream) |
| :--- | :--- | :--- |
| **L1 (最高级)**<br>硬件级 TEE 保护<br>(如: 4K 电视, 高端手机) | **L1 License**<br>(包含 4K 密钥) | **4K HDR / 1080p 高码率**<br>(最高画质) |
| **L3 (最低级)**<br>软件级保护<br>(如: 普通 PC 浏览器, StreamFab) | **L3 License**<br>(包含 1080p 密钥) | **1080p / 720p / 540p**<br>(被阉割的画质) |

### 4.2. StreamFab 的“战略性放弃”是什么意思？
当 StreamFab 想要下载一部 4K 电影时：

1.  **尝试 (Try):** StreamFab 伪装成 L3 设备（因为它只有 L3 的钥匙），向 Netflix 喊话：“给我 4K 的流！”
2.  **被拒 (Reject):** Netflix 服务器一看：“你是 L3 设备？对不起，4K 内容只给 L1 设备。滚。” (返回 403 或只返回 1080p 列表)。
3.  **降级 (Fallback):** StreamFab 碰了一鼻子灰，只能退而求其次：“好吧，那给我 1080p 的流总行了吧？”
4.  **成交 (Accept):** Netflix 服务器：“1080p 可以，给你。”

**这就是“降级”：**
不是 StreamFab *不想* 下 4K，而是因为它手里那张“身份证 (L3 CDM)”级别不够，服务器**根本不给它发** 4K 的数据包。

### 4.3. 深入解剖：服务器是如何“看人下菜碟”的？
**用户追问：** "那意思就是视频流是区分不同标准的？针对不同设备、用户订阅情况给不同级别的流？"

**答案：是的。这是一个物理隔离 + 动态菜单的组合拳。**

#### A. 物理层：CDN 上存着什么？
Netflix 的仓库里，同一部电影实际上存了**几十个不同的文件**（Representations）：
*   `movie_4k_hdr.mp4` (需要 L1 钥匙)
*   `movie_1080p_high.mp4` (需要 L1 钥匙)
*   `movie_1080p_std.mp4` (需要 L3 钥匙) <-- StreamFab 的目标
*   `movie_720p.mp4` (需要 L3 钥匙)
*   ...

#### B. 逻辑层：给你看什么菜单？(Dynamic Manifest)
当你点击播放时，服务器会根据你的 **设备 (Device)** 和 **订阅 (Subscription)**，动态生成一份 **MPD (播放列表/菜单)** 给你。

*   **场景 1：尊贵组合 (L1 设备 + 4K 会员)**
    *   **菜单内容：** 包含 `4K HDR`, `1080p High`, `1080p Std`, ...
    *   **结果：** 你可以请求 4K 文件的钥匙，服务器也会给你发。

*   **场景 2：StreamFab 组合 (L3 伪装设备 + 4K 会员)**
    *   **菜单内容：** 只有 `1080p Std`, `720p`, ... (**4K 的选项直接被服务器删掉了！**)
    *   **结果：** 你根本看不到 4K 的下载链接。就算你通过黑客手段猜到了 4K 的链接去请求，服务器也会在发钥匙环节再次校验：“你是 L3 设备，不准开 4K 的锁”，然后拒绝你。

#### C. 结论
所谓“发片策略”，就是服务器在**“给菜单”**和**“给钥匙”**这两个环节，严格审查你的身份。
StreamFab 因为伪装的是 L3 身份，所以它注定**“在菜单上看不到 4K，在钥匙上拿不到 4K”**。

### 4.4. 身份是如何判定的？(The Identity Verification)
**用户疑问：** "这个身份用什么判定？设备吗？"

**答案：是的，但不是靠你说你是谁，而是靠‘数字身份证’ (Device Certificate)。**

#### 1. 绝对不能靠“嘴” (User-Agent 是没用的)
普通的 HTTP 请求里，浏览器会发一个 User-Agent 字段（比如 `Mozilla/5.0... Android 10...`）。
*   **对于普通网站：** 你改个 User-Agent 就能伪装成 iPhone。
*   **对于 DRM：** 这招完全无效。Netflix **根本不看** User-Agent。

#### 2. 必须出示“身份证” (Device Certificate)
在 DRM 的世界里，每个经过认证的设备（无论是电视、手机还是浏览器），在出厂时都会被烧录一个 **Device Certificate**。
*   **颁发机构：** Google Widevine CA (根证书机构)。
*   **内容：** 包含设备的唯一 ID、**安全级别 (Security Level)**、以及公钥。
*   **防伪签名：** 这个证书被 Google 的私钥签名过。**你无法篡改里面的任何一个字**（比如把 L3 改成 L1），一旦篡改，签名校验就会失败。

#### 3. 为什么 L1 无法伪造？
*   **L3 证书：** 通常作为文件存在系统分区里。黑客（StreamFab）可以把这个文件拷贝出来，只要不改动内容，它就是有效的 L3 身份证。
*   **L1 证书：**
    *   它不是一个文件，它是**烧死在 CPU 的安全芯片 (TEE/TrustZone)** 里的。
    *   它的私钥永远出不来。
    *   StreamFab 即使把 L1 的证书（公钥部分）抄下来发给 Netflix，Netflix 发回来的加密包，StreamFab 也打不开（因为没有芯片里的私钥）。

**总结：**
身份判定靠的是 **Google 签名的数字证书**。
StreamFab 之所以只能伪装成 L3，是因为它**只能偷到 L3 的证书文件和私钥**。L1 的私钥在芯片里，偷不到，所以伪装不了。

## 🔵 Level 4: 苹果生态 (FairPlay Streaming)

常见于 Apple TV+, iTunes 内容。

*   **🛡️ 加密策略 (Defense):**
    *   苹果自家的 DRM 体系，逻辑与 Widevine 类似，但绑定苹果硬件生态。
    *   **SPC/CKC 流程:** 类似于 Widevine 的 Challenge/Response，但协议完全不同。
*   **⚔️ 破解/下载方案 (Tactics):**
    *   **跨平台攻击:** 很多 Apple TV+ 的内容在非苹果设备上播放时，会回退到 Widevine DRM。下载器通常会抓这个漏洞，**伪装成 Chrome 浏览器访问 Apple TV 网页版**，强行把战场拉回到 Widevine L3 的领域来解决。
    *   **难度:** ⭐⭐⭐⭐ (取决于是否有网页版入口)

## 总结：StreamFab 的能力边界

| 场景 | 网站举例 | 加密策略 | StreamFab 策略 | 结果 |
| :--- | :--- | :--- | :--- | :--- |
| **普通视频** | YouTube, 91Porn | 无 / Clear Key | 直接下载 | ✅ 成功 |
| **会员电影** | Netflix, Amazon | Widevine L3 | **伪装成手机 (L3 CDM)** | ✅ 成功 (最高 1080p) |
| **4K 大片** | Netflix 4K | Widevine L1 | **无解 (或降级)** | ❌ 只能下 1080p |
| **苹果独占** | Apple TV+ | FairPlay | **切到网页版 (Widevine)** | ✅ 成功 |
