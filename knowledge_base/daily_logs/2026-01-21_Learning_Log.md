# 📅 2026-01-21 学习日志：DRM 与 StreamFab 机制深度解析

## 1. 核心流程：下载与解密的时序
*   **误区修正：** 不是下载完文件才去拿钥匙，而是 **“不见兔子不撒鹰”**。
*   **正确时序：**
    1.  **Analysis (分析):** 拿到 Manifest (PSSH)，知道有锁，但不动手。
    2.  **Action (点击下载):** 用户触发。
    3.  **License Acquisition (拿钥匙):** **下载前的一瞬间**，伪装成 Android 设备向服务器请求。
    4.  **Download & Decrypt (并行):** 拿到 Key 后，下载分片 -> 内存解密 -> 写入硬盘。

## 2. 关键组件：Android CDM
*   **本质：** 一个“自带身份证的数字保险箱”。
*   **核心资产：**
    *   **Device Private Key (私钥):** 从真实手机提取，用于解开服务器发的“信封”。
    *   **Device Certificate (证书):** Google 签名，用于向服务器证明“我是良民”。
*   **作用：** 它是唯一能与 License Server 对话并解开 Response 的组件。

## 3. 核心概念：License Server (许可证服务器)
*   **定义：** DRM 体系中的最高权力机构，负责分发“视频密码”。
*   **三大模块：**
    1.  **业务门卫 (Business Logic):** 检查“你是谁？买了票吗？在哪个国家？” (Cookie/Token 验证)。
    2.  **密钥金库 (Key Database):** 存储所有电影的原始 AES 密钥。
    3.  **打包员 (DRM SDK):** 使用 Google 的算法，把 AES 密钥用设备的公钥加密打包。
*   **工作流：** 收到请求 -> 验票 -> 查库拿钥匙 -> 加密打包 -> 返回。
