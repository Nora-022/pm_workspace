【SF 插件】Common 逻辑规范​

1. 文档定位与适用范围​

1.1 文档定位​

本规范用于定义 StreamFab 浏览器插件的 通用逻辑规则与系统行为约束。​

Common 文档用于描述：​

•

插件生命周期的固定结构；

•

各核心模块的统一行为规则；

•

所有插件必须遵循的系统级约束。

插件差异通过

【SF 插件】能力声明表规范（V1.0）进行声明，并在插件需求文档中展开。​

1.2 适用范围​

本规范适用于所有 StreamFab 浏览器插件，包括但不限于：​

•

单站点插件；

•

多站点插件；

•

试用与订阅插件。

所有插件在设计与实现时，必须遵循本规范中定义的逻辑与约束，不得自行修改或绕过。

1.3 文档分层关系​

•

Common 逻辑规范​

定义系统固定流程与不可变规则。​

•

能力声明表

用于声明插件在 Common 规则下的能力参数与策略选择。​

•

插件需求文档

在 Common 与能力声明约束下，定义具体的产品交互与功能设计。​

1.4 约束原则​

•

Common 文档不定义 UI 表现、交互细节或文案内容；​

•

Common 文档不约束具体技术实现方式；​

•

所有系统级行为，如未在能力声明中明确为可变项，均视为通用规则。

2. 插件运行周期与数据生命周期​

2.1 插件运行周期​

插件的运行周期以浏览器启动到浏览器关闭为边界。

在一次浏览器运行周期内，插件保持持续运行状态，页面刷新、页面跳转或站点切换，不会中断插件

运行周期。

2.2 数据保留规则​

在一次浏览器运行周期内，插件产生的数据持续保留，包括但不限于：

•

视频检测结果；

•

视频分析结果；

•

下载任务及其状态记录。

上述数据不会因页面刷新、页面跳转或站点切换而被自动清除。

2.3 数据清除规则​

插件运行期间产生的数据，仅在以下情况下被清除：

•

用户主动执行清除缓存操作；

•

浏览器被关闭并重新启动。

除上述情况外，插件不得自动清除检测数据、分析结果或下载记录。

2.4 Detection Session 与数据关系​

插件可在运行周期内维护一个或多个 Detection Session，用于组织检测与分析过程。​

•

Detection Session 的结束不等同于数据清除；​

•

不同 Detection Session 之间的数据相互隔离；​

•

当用户回到原有 Detection Session 时，该 Session 内的数据仍然存在。​
