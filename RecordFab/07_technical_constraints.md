# 07 技术约束（Technical Constraints）

## 系统要求（已确认）
- 当前支持平台：仅 Windows
- 操作系统：Windows 11 / 10 / 8.1 / 8 / 7（32/64 bit）
- CPU：Intel i3 或以上
- 内存：4GB RAM 或以上
- 磁盘：40GB 可用空间或以上
- 网络：需要持续联网
- 授权：使用时必须联网验证

## 已确认的能力约束
1. 输出规格约束
- 当前公开为 720p / 1080p。
- 输出格式当前公开为 MP4。

2. 站点能力约束
- 虽然支持大量流媒体站点，但高速录制并非全站点都可用。
- 具体表现为：部分站点只能以 1x 录制。

3. 运行时约束
- 录制过程中，RecordFab 内的其他操作会被限制，以保证更平滑的录制。
- 这意味着交互设计不能假设用户能在同一会话里自由切换大量其他功能。

4. 当前公开可配置项约束
- FAQ 当前明确支持的自定义项只有：
  - 输出分辨率
  - 录制速度

5. 当前版本能力边界
- 支持 `MP4 / MKV` 输出。
- 不支持队列录制。
- 不支持自动录制。

6. 设置项边界
- 除录制核心参数外，还存在通用设置项，例如输出目录。
- 这类设置项应与录制核心参数分层表达，避免混在录制确认弹窗里。

7. 内部资料中的技术补充
- 底层曾提到“录制模式”和 “Re-encoding 模式”组合。
- 当前可作为已知背景知识，但不要在没有研发确认的情况下直接转写为对外功能承诺。

## 推定约束（待内部确认）
1. 录制期间可能需要目标内容保持稳定播放。
2. 后台最小化录制能力未确认，不应在 PRD 中默认支持。
3. 多任务并发录制能力未确认，不应默认设计复杂队列系统。

## 对设计和 PRD 的约束要求
1. 任何新功能都不能突破当前公开的系统要求口径。
2. 任何“后台运行”“定时录制”“云端同步”等提案都应先过技术可行性确认。
3. 对站点差异必须允许按站点降级，而不是统一承诺。
