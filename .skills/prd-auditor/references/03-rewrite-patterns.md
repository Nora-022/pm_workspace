# Rewrite Patterns (建议改写范式)

目标：让审计输出可直接回填 PRD，而不是停留在抽象建议。

## Pattern A: 模糊目标 -> 可验证目标

- 原始："提升用户体验"
- 改写："关键路径操作步骤 <= 3；关键页面 P95 响应 < 500ms（待确认）"

## Pattern B: 只有成功流 -> 补齐异常流

- 原始："点击下载后开始任务"
- 改写："点击下载后进入队列；若网络中断则自动暂停并在恢复后续传；若磁盘不足则暂停并提示更改路径。"

## Pattern C: 权限口语化 -> 规则化

- 原始："VIP 可用"
- 改写："Annual/Lifetime 可用；Free/Trial 不可用并展示升级入口。"

## Pattern D: 状态缺失 -> 状态机化

- 原始："任务处理中"
- 改写："Pending -> Running -> (Paused | Failed | Completed)，失败码需映射可恢复性。"

## 输出约束

- 每个 S0/S1 问题至少给 1 条可替换改写。
- 改写必须包含触发条件和结果，不得只改措辞。
