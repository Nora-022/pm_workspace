# 05 设计原则与规范（Design Principles）

## 设计原则（3-5 条）
1. 意图优先，异步校验（Intent First, Async Validation）
2. 局部反馈，拒绝打断（Localized Feedback, No Interruption）
3. 上下文严格绑定（Strict Context Binding）

## 每条原则的对/错示例

### 原则：意图优先，异步校验
- 对：用户点击下载后立即创建任务并跳转 Downloads；环境问题在任务卡片中异步反馈（如磁盘不足）。
- 错：点击下载后先做技术环境阻断校验，任务未创建，要求用户重复操作。

### 原则：局部反馈，拒绝打断
- 对：下载失败时在任务卡片内展示红色错误文案（Error Code + 原因），并提供 Retry。
- 错：下载失败时使用全局弹窗或浏览器级 Alert 打断操作；或将整条状态条改成红色造成过度警示。

### 原则：上下文严格绑定
- 对：Detected 列表与当前页面 URL 生命周期绑定；页面刷新或跳转后立即清空并重新检测。
- 错：页面切换后保留上一页面检测结果，导致用户处理“幽灵”任务。

## 视觉规范
- 字体：跟随插件当前语言包与平台默认可读性字体。
- 字号层级：标题 > 模块标题 > 正文 > 辅助信息，保持统一层级与间距。
- 颜色语义：
  - 主色：主操作按钮与可点击关键入口。
  - 成功：任务完成、可用状态。
  - 警告：接近配额上限、可恢复风险。
  - 错误：仅用于错误文案与错误码，不将整条状态条全量染红。
- 间距系统：保证 Popup / Sidebar 双模式下卡片密度一致，避免模式切换导致阅读跳变。

## 组件规范
- 按钮（主/次/危险）：
  - 主按钮用于关键动作（Download、Install CoApp、Confirm）。
  - 次按钮用于辅助动作（Force Refresh、Learn More）。
  - 危险按钮仅用于不可逆删除。
- 输入框：即时校验格式，错误提示就地展示，不用全局弹窗。
- 弹窗：仅用于商业级阻断（如试用结束、订阅过期、额度耗尽），技术异常优先卡片内反馈。
- 表格/列表：下载任务以卡片列表为核心，状态与操作同位展示，支持快速 Retry/Cancel/Open Folder。
